# 下班彩蛋 · 大肥鱼跑出窗口到桌面撒欢 —— 实施计划

> 目标：到达下班时间时，除了窗口内的撒花/表情清除，让大肥鱼**从画布（主窗口）里"钻出来"**，
> 在 Windows 桌面上**来回跑一跑、边跑边喊"下班啦"**，跑完带着一句彩蛋消失。纯本地、不联网。

---

## 1. 现状（读完代码的结论）

| 环节 | 现在怎么做的 | 位置 |
| --- | --- | --- |
| 到点判定 | `render()` 里 `phase === 'after'`，每个自然日只触发一次 | `src/app.js` L323–336 |
| 到点表现 | `celebrate()` 撒花 + `mascot.playMilestone('done')`（余额-钱袋满溢） | `src/app.js`、`src/pet.js` |
| 通知/提示音/记账 | `finishDay()` → 系统通知 + 合成提示音 + 写历史 | `src/app.js` |
| 主窗口 | 420×620 无边框、**透明背景**、置顶浮层 | `electron/main.cjs` L568–635 |
| 桌宠 | 96 个 webm 透明动画（VP9 alpha），`pet.js` 调度情绪/摸鱼/彩蛋 | `src/pet.js`、`assets/pet/all/*.webm` |
| 安全边界 | `contextIsolation`+`sandbox`+CSP `default-src 'none'`、禁导航/开窗 | `main.cjs` / `index.html` |

**关键利好**：主窗口本来就是透明无边框，桌宠是透明 webm——"跑出去"在观感上完全可以做到。

**关键技术事实**：渲染进程在 sandbox 里拿不到屏幕坐标/多显示器信息，窗口来回移动只能由**主进程**用
`screen.getPrimaryDisplay().workArea` + `BrowserWindow.setBounds()` 完成（Electron 45 支持）。

这个能力**目前完全不存在**，属于新功能。

## 2. 方案对比

| 方案 | 观感 | 复杂度 | 风险 | 结论 |
| --- | --- | --- | --- | --- |
| **A. 专用透明覆盖窗**：新建一个全屏透明置顶窗，把大肥鱼"吐"进去沿桌面跑 | ★★★★★ 真的跑出主窗口、桌面任意位置跑 | 中 | 覆盖窗若拦截点击会影响办公，需 `setIgnoreMouseEvents` | ✅ **主推** |
| **B. 主窗口自己滑跑**：临时把 420×620 主窗缩小成鱼、满桌面移动，结束后复原 | ★★★ 也算"出去跑"，复用现有窗口 | 低 | 窗口被挪动/尺寸变化，用户正拖拽时冲突；最小化/置顶状态要恢复 | ✅ 作为**降级/单窗兜底** |
| C. 纯窗口内动画（不离开窗口） | ★★ 达不到"出画布"诉求 | 极低 | 无 | ⛔ 不满足需求 |

**决策：以 A 为主，B 作为失败兜底**。两者共用同一套"跑步计划"脚本，主进程负责窗口搬运，渲染层只负责
把鱼画出来 + 说话气泡。

---

## 3. 主方案（A）设计

### 3.1 新窗口
- 新增 `electron/runner.cjs` 专用的**独立渲染页** `src/runner.html`（只放 `runner.js` + `runner.css`）。
- `BrowserWindow`：`frame:false, transparent:true, alwaysOnTop:true(level 'screen-saver'), skipTaskbar:true,
  resizable:false, focusable:false, hasShadow:false, show:false`，`setIgnoreMouseEvents(true, {forward:true})`
  防拦截点击。
- 生命周期：只在**下班彩蛋期间**存在，跑完销毁；崩溃/超时也有兜底销毁。

### 3.2 跑步路线（主进程驱动）
1. 主进程计算：主窗当前位置 → 判断哪一侧离屏幕边缘近，往那一侧"钻出"；
2. 生成一条**来回奔跑**的分段路径（左→右→左，2~3 趟），每段用 ~60fps 的定时器插值 `setBounds`；
3. 每到一个"落脚点"通知渲染层播一个动作 + 说一句话（见 3.4）；
4. 跑完在某个位置停住、撒花/鞠躬、淡出，销毁窗口。

### 3.3 出画布过渡
- 用主窗当前 `getBounds()` 得到鱼在屏幕上的大致位置，覆盖窗第一帧就从这个坐标附近"冒出"，
  然后沿路径跑。视觉上是从主窗"跳出来"。
- 若主窗在屏幕外/最小化，直接从工作区底部中央冒出。

### 3.4 边跑边说（气泡）
渲染层根据主进程推送的 `{clip, line}` 事件：
- 播放 `a012 侧身急躁跑 / a061 开心小跑 / a020 原地左转奔跑` 等 move 动画；
- 头顶气泡显示文案池（随机）：
  - 「下班啦——！」「溜了溜了～」「今天的钱我赚够啦！」「谁也别拦我！」
  - 「明天见👋」「老板看不见我，我看不见老板」「干饭去咯！」
- 气泡里可带今日已赚金额（`¥xx`）增加彩蛋感。

### 3.5 彩蛋（选项）
- 跑到一半有个"小跳跃/转圈"（`a023`），到终点撒花+鞠躬；
- 偶尔喊一句**整点/节日**台词（复用现有 festival 动画可选）；
- 与现有 `celebrate()` 撒花、`playMilestone('done')` 共存不冲突（主窗那套照旧，覆盖窗是额外彩蛋）。

## 5. 安全 / 兼容 / 降级

- **安全**：新覆盖窗同样 `contextIsolation:true, nodeIntegration:false, sandbox:true`；CSP 与主窗一致
  （`media-src 'self'`，CSP 不允许新协议，沿用相对路径 `../assets/pet/all/*.webm`）；仅主进程可创建，渲染不可提权。
- **不打扰**：`setIgnoreMouseEvents(true)` 让点击穿透；`skipTaskbar`；`focusable:false`；只在彩蛋期存在。
- **尊重降低动效**：`reduceMotion` 时**不跑**，退回窗口内撒花。
- **单实例/多显示器**：路径限制在光标/主窗所在显示器的 `workArea`，不出界；跨屏不做（简单、稳）。
- **失败兜底**：覆盖窗创建失败 → 方案 B（主窗临时瘦身跑）→ 再失败就静默，绝不影响 `finishDay()`。
- **性能**：只移动小窗 + 1~2 个 webm 解码，跑 6~10 秒，结束后释放。

## 7. 验收标准

- [ ] 到点后大肥鱼从主窗位置"钻出"，在桌面上**来回跑 ≥2 趟**，头上连续换**不同"下班啦"台词**。
- [ ] 跑完自动收尾消失，主窗原有撒花/通知/记账/表情清除**不受影响**。
- [ ] 奔跑期间**鼠标点击不被拦截**，任务栏无新图标，不抢焦点。
- [ ] 开启"降低动态效果"时**不跑**（走原撒花）。
- [ ] 关闭开关后不触发；`runner` 窗口任何异常都不影响下班主流程（超时销毁）。
- [ ] `node --test "tests/*.mjs"` 全绿。
