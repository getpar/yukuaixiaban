## 1. 产品定位

**一句话：** 一个常驻桌面的下班倒计时小应用，用「赚了多少」和「还有多久」把上班时间变得可视化，再让一只情绪随下班临近逐渐变好的大肥鱼陪着你。

### 1.1 解决什么问题

- 上班时想知道“我还要熬多久”，但不想反复看手机或打开日历。
- 想知道自己的时间到底值多少钱，把抽象月薪变成每分钟、每秒的即时反馈。
- 工作日需要一点轻量、无打扰的情绪价值，而不是又一个复杂效率工具。

### 1.2 设计原则

1. **打开就能看懂**：核心信息不超过三眼——还剩多久、已经赚多少、每分钟赚多少。
2. **轻量常驻**：小窗口、无边框、可置顶，不占工作区，不打断工作。
3. **有情绪但不吵闹**：大肥鱼是陪伴，不是弹窗广告；动效可关闭。
4. **数据只留在本机**：工资和工作时间不上传、不联网、不埋点。
5. **开机即用**：首次设置一次，之后自动按当天时间运行。

### 1.3 非目标（v1.0 不做）

- 账号体系、云同步、多设备同步。
- 考勤打卡、加班申请、请假/调休管理。
- 工资条、个税、社保、到手工资精算。
- 多班次排班、跨城市时区。
- 桌面宠物自由拖动、皮肤商店、社区上传。
- 移动端 / macOS / Linux 适配。

## 2. 用户与使用场景

### 2.1 目标用户

- 固定或相对固定上下班时间的上班族。
- 喜欢 DeepSeek 大肥鱼形象、喜欢有点梗的桌面小工具的人。
- 想直观感受“时间就是金钱”的人。

### 2.2 核心场景

| 场景 | 用户动作 | 应用反馈 |
| --- | --- | --- |
| 早上到工位 | 打开应用 | 大肥鱼瘫在工位上；显示距下班时间，今日已赚从 0 开始 |
| 工作中瞥一眼 | 看桌面角落 | 已赚金额慢慢上涨，每分钟收入清晰可见 |
| 下午犯困 | 看大肥鱼 | 鱼从“生无可恋”逐渐变得有精神，配一句吐槽 |
| 临近下班 | 看倒计时 | 鱼开始雀跃，进度条接近满格，显示“今天还能赚” |
| 下班瞬间 | 应用自动切换 | 撒花庆祝，显示“下班啦，今天也辛苦啦” |
| 第二天再打开 | 自动按当天时间运行 | 重新开始新一天的计时，无需再次设置 |

## 4. 核心体验流程

```text
首次打开
  └─ 欢迎 + 设置面板（预填 09:00 / 18:00，工资为空）
       └─ 填写月薪（或切换时薪）→ 保存
            └─ 主界面
                 ├─ 上班前：大肥鱼睡觉，显示距上班时间
                 ├─ 上班中：倒计时 + 赚钱进度 + 情绪成长
                 └─ 下班后：撒花完成态，显示今日总收入

日常打开
  └─ 读取本地设置 → 根据当前时间直接进入对应状态 → 窗口恢复到上次位置
```

## 6. 功能规格

### 6.1 工资计算

#### 月薪模式

```text
班次分钟数 = 下班时间 - 上班时间
日薪       = 月薪 ÷ 每月计薪天数
每分钟收入 = 日薪 ÷ 班次分钟数
今日已赚   = 日薪 × 当前工作进度
今日还能赚 = max(日薪 - 今日已赚, 0)
```

#### 时薪模式

```text
每分钟收入 = 时薪 ÷ 60
日薪       = 每分钟收入 × 班次分钟数
今日已赚   = 每分钟收入 × 已工作分钟数
```

#### 计算示例

月薪 ¥12,000，每月计薪 21.75 天，09:00–18:00（540 分钟）：

```text
日薪       = 12000 ÷ 21.75        = ¥551.72
每分钟收入 = 551.72 ÷ 540         = ¥1.02
15:45 时   = 已工作 405 分钟
今日已赚   = 405 × 1.0217         = ¥413.79
今日还能赚 = 551.72 - 413.79      = ¥137.93
```

#### 计算规则

- 金额保留完整精度参与计算，只在展示时格式化；每分钟收入展示 2 位小数，已赚金额展示 2 位小数。
- 默认把上班到下班之间的全部时间计入（**午休也照常赚钱**），避免 v1 引入复杂的午休切分；P2 再提供“扣除午休”选项。
- 工作进度 = `已工作秒数 / 班次总秒数`，限制在 `0–1`。
- 上班前进度为 0，已赚为 0；下班后进度为 1，已赚等于日薪。
- 跨夜班次：下班时间 ≤ 上班时间时，视为次日下班；当前时间早于下班时间时，班次起点按前一天计算。
- 上班时间与下班时间相同视为无效配置。
- 所有时间按系统本地时区计算，不做时区转换。

### 6.2 时间刷新策略

- 每 250ms 重新读取一次 `Date.now()`，重新计算进度和金额；倒计时按秒展示。
- 不采用“每秒累加”的方式，避免窗口休眠、系统卡顿、修改系统时间导致累计误差。
- 跨过 00:00 自动进入新一天；窗口从睡眠恢复后，下一次 tick 立即校正。
- 到达下班时间后切换到完成态；每个自然日只播放一次撒花庆祝。

### 6.3 大肥鱼情绪系统

情绪只由**当天工作进度**决定，不受具体钟点影响；上班前和下班后是独立状态。

**形象方案（v0.5 更新）**：采用社区项目 [dsh-pet](https://github.com/PC2005-cloud/dsh-pet) 提供的「蓝鲸娘 / 大肥鱼」透明动画，**96 个动画全部接入**（640×360 VP9 alpha，约 45.6 MB），许可为 **CC BY-NC-SA 4.0**，仅个人非商业使用，署名见 `THIRD-PARTY-NOTICES.md`。仓库内同时保留原创 SVG 版（`src/mascot.js`），可通过 `src/app.js` 一行 import 切换。

**三层调度：**

| 层 | 触发 | 用到的动画 |
| --- | --- | --- |
| 基础情绪 | 随工作进度切换 | 7 个（见下表） |
| 随机摸鱼 | 上班中每 25–60 秒 | 吃 / 玩 / 走动 / 工作小动作 / 杂项共 60+ 个；鱼饼瘫、灵魂出窍时约 30% 概率改播「打瞌睡 / 被惊醒」 |
| 彩蛋 | 整点前后（55–65 分钟随机） | 节日 10 个 + 撒欢 4 个 + 余额 6 个 |
| 里程碑 | 今日已赚跨过 25% / 50% / 75% / 100% | 余额-数金皱眉 → 钱袋如常 → 金袋叮当 → 钱袋满溢 |
| 点击 | 点击形象 | 点击回应 5 个 |

每次动作播完自动回到当前情绪；`tests/pet-manifest.test.mjs` 会校验「96 个动画每一个都至少被某一层调度到」，避免有素材永远播不到。

| 进度 | 状态名 | 选用动画 | 表现 | 气泡文案（示例） |
| --- | --- | --- | --- | --- |
| 上班前 | 沉睡鱼 | 睡觉-循环 | 趴在桌上睡着，头顶 Zzz | “再睡五分钟……就五分钟……” |
| 0%–15% | 鱼饼瘫 | 工作状态-垂头叹气冒汗 | 垂头丧气、冒汗 | “工位好硬，人生好难。” |
| 15%–40% | 灵魂出窍 | 哈欠连天 | 张大嘴打哈欠、伸懒腰 | “眼睛睁着，脑子关机。” |
| 40%–65% | 逐渐回魂 | 工作状态-原地踱步张望 | 原地踱步、左右张望 | “再熬一下，下午就过去一大半了。” |
| 65%–85% | 眼里有光 | 期待开饭 | 眼神发亮、跃跃欲试 | “闻到下班的味道了！” |
| 85%–100% | 归心似箭 | 工作状态-雀跃庆祝 | 原地雀跃、蹦跳 | “最后冲刺！谁也别拦我下班！” |
| 100% | 下班撒花 | 放烟花 | 挥舞烟花、庆祝 | “下班啦！今天也辛苦啦 🎉” |

**交互：**

- **戳一下**：随机播放「点击回应-元气挥手 / 点击回应-开心跃动」，气泡换一句该情绪下的吐槽（约 2.6 秒后恢复常规文案）。
- **视线跟随**：鼠标在窗口内移动时，形象做轻微视差位移（`--look-x/--look-y`）。
- **降低动态效果**：暂停视频解码、只保留当前静帧；系统 `prefers-reduced-motion` 时同样生效。

**实现方式：**

- 每个情绪一个 `<video muted loop playsinline preload="auto">` 叠放，通过 `opacity` 过渡切换，只播放当前档。
- 视频自带 alpha 通道，直接叠在深色渐变背景上，无需抠像或混合模式。
- 点击动作用独立图层播放一次，`ended` 后回到当前情绪；带 6 秒兜底定时器。
- **避免重影的两条硬规则**（v1.1.1）：
  1. 播一次性动作时，基础情绪层立刻暂停并隐藏（根节点挂 `is-action`，CSS 直接 `opacity: 0`），任何时候只允许一层视频在播；
  2. 不给视频加 `filter: drop-shadow`——带 alpha 的视频在移动时会被滤镜拖出一条模糊轮廓，看起来像重影。
- 素材本身是 24fps、无运动模糊；快速动作的轻微顿挫来自帧率本身，不是渲染叠加。
- 原创 SVG 版仍保留完整 7 档 + 待机微动画 + 撒花能力，作为无素材依赖的备选。

#### 6.3.1 原创 SVG 备选形象（v0.3 增补，v0.4 起非默认）

> 这一节描述仓库内保留的原创 SVG 版大肥鱼（`src/mascot.js`）。它不使用任何第三方素材，适合需要商用或无素材依赖的场景；默认形象已切换为上一节的社区桌宠动画。

| 能力 | 触发 | 表现 |
| --- | --- | --- |
| 戳一下 | 点击大肥鱼 | 挤压回弹 + 按状态爆出粒子（水花/爱心/星星/彩纸），气泡换一句吐槽（约 2.6 秒后恢复常规文案） |
| 视线跟随 | 鼠标在窗口内移动 | 眼球与头部朝指针方向轻微偏移，离开窗口回正 |
| 随机眨眼 | 待机自动 | 各情绪节奏不同：沉睡闭眼、鱼饼瘫慢眨、归心似箭瞪眼快速眨 |
| 呼吸/摆尾/扇鳍 | 待机自动 | 幅度与频率随情绪递增，全程只动 `transform` |

性能与降级：页面不可见（`document.hidden`）或开启减少动态时暂停随机调度与位移动画，只保留表情与配色变化。

### 6.4 设置与持久化

设置项（含默认值）：

```json
{
  "version": 1,
  "salaryType": "monthly",
  "monthlySalary": null,
  "monthlyWorkdays": 21.75,
  "hourlyRate": null,
  "workStart": "09:00",
  "workEnd": "18:00",
  "alwaysOnTop": true,
  "reduceMotion": false
}
```

- 首次启动 `monthlySalary` 为空，自动打开设置面板，工资输入框聚焦。
- 其余字段预填默认值，用户只需输入工资即可开始。
- 保存时校验：工资 > 0、计薪天数 > 0、时间有效、班次时长 > 0。
- 保存在 `%APPDATA%/鱼快下班/settings.json`（Electron `userData` 目录），写入采用临时文件替换，避免断电损坏。
- 窗口位置、尺寸单独保存在 `window-state.json`；位置越界时回退到默认位置。
- 设置修改后立即生效，无需重启。
- 不收集任何个人信息，不发起网络请求。

### 6.5 托盘与窗口行为
- 托盘图标：蓝色大肥鱼剪影；悬停提示“鱼快下班 · 距下班 02:13:45”。
- 托盘菜单：显示/隐藏窗口、始终置顶（勾选）、设置、退出。
- 点击托盘图标：切换显示 / 隐藏。
- 关闭按钮：退出应用（v1 不做“关闭到托盘”，避免用户困惑）；最小化按钮：最小化到任务栏。
- 重复启动：唤醒已有窗口并置顶，不创建第二个实例。
- 窗口位置超出当前屏幕时，自动回到默认位置。

## 6.6 P1 / P2 新增能力（v0.6）

### 6.6.1 时薪模式（P1）

设置面板顶部用分段控件切换「月薪 / 时薪」：

- 月薪：月薪 + 每月计薪天数（默认 21.75）
- 时薪：只填时薪（元/小时）
- 内核侧 `payFor` 已同时支持两种：时薪模式 `perMinute = 时薪 ÷ 60`，`dailyPay = perMinute × 有效班次分钟数`
- 切换时只显示对应输入框，校验和错误提示跟随切换

### 6.6.2 午休不计薪（P2）

- 设置里打开「午休不计薪」后填午休起止（默认 12:00–13:00）。
- 计算口径：
  ```text
  有效班次   = 班次总时长 − 午休时长
  有效已工作 = 已过时间 − 落在午休里的时间
  progress   = 有效已工作 ÷ 有效班次
  每分钟收入 = 日薪 ÷ 有效班次分钟数
  ```
- 午休期间 `kind = 'lunch'`：进度与金额冻结，大肥鱼进入睡觉状态，状态栏显示「午休中」，倒计时仍是真实下班时间。
- 跨夜班次用「相对上班时刻的分钟偏移」判断午休是否落在班次内；午休在班次外时自动忽略。

### 6.6.3 下班提醒（P2）

- **系统通知**：到点后主进程弹 Windows 通知「下班啦 🎉 · 今天赚了 ¥xxx，收拾东西回家吧」。
- **提示音**：渲染进程用 WebAudio 现场合成三音提示（不依赖音频文件），通知本身默认静音以免响两次。
- 两项都可单独关闭；每个自然日只触发一次。

### 6.6.4 开机自启（P2）

- 设置里开关，主进程调用 `app.setLoginItemSettings({ openAtLogin })`；便携版优先使用 `PORTABLE_EXECUTABLE_FILE` 路径注册。
- 开关状态写回 `settings.json`，下次启动时同步。

### 6.6.5 历史记录（P2）

- 每天进入「下班啦」状态时记一笔：`{ date, earned, dailyPay }` 写入 `userData/history.json`，同日覆盖，保留最近 60 天。
- 设置面板「记录」页显示最近 7 天：合计、日均、逐日金额。
- 全部本地存储，不上传。

### 6.6.6 自定义形象（P2）

- 设置面板「形象」区可选择本地图片（png/jpg/jpeg/gif/webp）或视频（mp4/webm）替换内置桌宠。
- 主进程把文件复制到 `userData/mascot/`，通过自定义协议 `xb-media://local/<文件名>` 提供给渲染层；协议只允许该目录内、白名单扩展名的文件，做了路径穿越与符号链接校验。

### 6.6.8 下班跑出桌面彩蛋（P3，v2 重做）

到点（进入 `after` 状态的那一帧）除原有撒花外，再触发一次"大肥鱼跑出窗口"的桌面彩蛋。
v2 参考优秀桌宠案例（Mocha Casa 的窗口运动/状态机、Shimeji 的朝向、modbender 的贴地与避让）重做，
重点解决 v1 的"脚底打滑/朝向错乱/气泡被裁/机器人匀速"观感问题。

- **独立覆盖窗（v3 丝滑版）**：主进程 `electron/runner.cjs` 临时创建一个
  `frame:false / transparent:true / alwaysOnTop(screen-saver) / skipTaskbar / focusable:false`
  的窗口，**一次性铺满整个工作区并保持静止**，并 `setIgnoreMouseEvents(true, {forward:true})`
  **点击穿透**，绝不挡办公、不抢焦点。
  - **为什么这么做（解决掉帧）**：v2 是「主进程每 16ms `setTimeout` + `setPosition` 移动小窗」，
    JS 定时器精度差、每次 `SetWindowPos` 都让合成器重排透明层，60fps 稳不住、会掉帧。
    v3 改为业界通行做法：**窗大而静止，鱼在窗内用 CSS `transform: translate3d()` 移动**——
    走 GPU 合成，渲染层用 `requestAnimationFrame` 自跑整条时间轴；主进程只在开跑时**下发一次**
    完整计划（keyframes/stages/beats），不再逐帧 IPC、不再逐帧 `setPosition`。实测 rAF 帧数
    约 3s/500 帧、6s/1000 帧（跑满显示器刷新率，无掉帧）。
- **路线（缓动 + 步频耦合）**：纯函数 `src/runner-plan.mjs` 的 `planRun()`：
  - 用 **梯形速度曲线**（`easeTrapezoid`：加速→匀速→减速）驱动位移，而非匀速或过尖的 cubic，
    峰值速度锁定在 `maxSpeedPx`（默认 560）以内；段时长由「距离 ÷ 巡航速度」推导，
    避免窗口移动远快于腿部步频而"滑冰"。
  - 跑线**贴工作区底部**（脚踩地面、避任务栏）；传入光标坐标时，若光标落在跑线上则整条线**抬高绕开**。
  - 分方向：每段带 `dir`（right/left），向左跑由渲染层镜像。
  - 完整小剧场：**钻出 → 跑 → 急停转身(spin) → 跑回 → 跳(hop) → 撒花(celebrate) → 挥手(wave) → 淡出**。
  - 所有坐标夹在工作区内不越界。渲染层按 rAF 时钟插值 `transform`，主进程不再逐帧移动窗口。
- **边跑边说（渲染层 `src/runner.js`）**：
  - 统一用**侧身跑素材 a012**（注意：源素材本身**朝左**跑——脸在左、头发/尾巴拖向右）。
    因此**向左跑保持原样、向右跑才镜像** `scaleX(-1)`，朝向始终与移动方向一致，不会"倒着跑"。
  - 渲染层自己用 `speedAt()` 算瞬时速度，本地微调 webm `playbackRate`（1.0→1.35），
    让腿速与位移耦合，进一步减少打滑（无需逐帧 IPC）。
  - 头顶**多行自适应气泡**（`max-width` + 自动换行，绝不裁切），台词来自 `RUN_LINES` 池，不自动闪没。
- **节奏档位**：`settings.desktopRunMode` = `active`（活跃，2 趟，约 12s）/ `calm`（安静，1 趟，约 9s）。
- **开关与降级**：`settings.desktopRun`（默认 true）控制是否启用；`reduceMotion` 或系统
  `prefers-reduced-motion: reduce` 时**不触发**；覆盖窗就绪超时（4s）、渲染进程崩溃、移动失败等
  任何异常都收敛为"彩蛋失败"，**不影响**通知 / 记账 / 撒花等主流程。渲染层同一分钟内重复触发会被
  主进程拒绝（防异常循环开窗）；保存设置、打开设置、退出时会先 `stopDesktopRun`。

## 7. 技术方案

### 7.1 选型

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **Electron + 原生 HTML/CSS/JS** | **采用** | 当前环境已具备 Node 24；无需额外编译器；CSS/SVG 适合做角色动效；打包成熟 |
| Tauri | 不采用 | 当前机器没有 Rust 工具链，引入成本高 |
| Python + PySide | 不采用 | 动效与界面质感实现成本更高，打包体积/兼容性不占优 |
| 纯网页 PWA | 不采用 | 不是真正的桌面常驻小窗，置顶、托盘、开机启动都不稳定 |

不引入 React/Vue：页面是单窗口单页面，原生 JS 足够，减少构建链和打包体积。计算逻辑独立为纯函数模块，便于单元测试。

### 7.2 进程架构

```text
┌──────────────── Electron 主进程 (main.cjs) ────────────────┐
│ BrowserWindow / Tray / 单实例锁 / 窗口置顶 / 读写设置文件     │
└───────────────────────┬────────────────────────────────────┘
                        │ IPC（contextBridge，白名单）
┌───────────────────────▼────────────────────────────────────┐
│ 预加载脚本 (preload.cjs)                                    │
│ 仅暴露 loadSettings / saveSettings / setPinned / close 等 API│
└───────────────────────┬────────────────────────────────────┘
                        │
┌───────────────────────▼────────────────────────────────────┐
│ 渲染进程 (index.html + app.js + styles.css + calc.mjs)       │
│ 时间 tick / 工资计算 / 状态机 / SVG 大肥鱼 / 设置面板          │
└────────────────────────────────────────────────────────────┘
```

安全基线：

- `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。
- 渲染进程不允许加载远程内容；CSP 仅允许本地资源。
- 禁用 `window.open`、外部导航、webview。
- IPC 只接受固定的、结构化的参数；主进程侧校验设置数据。

### 7.4 关键模块

- **calc.mjs**
  - `resolveShift(now, start, end)`：返回班次起止、状态、进度、剩余秒数；处理跨夜。
  - `computeSalary(settings, shift)`：返回日薪、每分钟收入、已赚、还能赚。
  - `validateSettings(settings)`：返回错误字段与提示。
  - `formatDuration(seconds)`：格式化为 `HH:MM:SS`。
- **app.js**
  - 启动时加载设置 → 无有效工资则打开设置。
  - 250ms tick；只在显示值变化时更新 DOM。
  - 根据进度切换大肥鱼状态；首次进入完成态触发一次撒花。
  - 设置面板的输入、校验、保存、取消。
  - 按钮与快捷键：`Esc` 关闭设置，`Ctrl+,` 打开设置。
- **main.cjs**
  - 单实例锁；无边框透明窗口；托盘；置顶状态；位置恢复。
  - 解析 `settings.json`，损坏或版本不兼容时回退默认值并备份原文件。
  - `will-navigate` / `setWindowOpenHandler` 全部阻止。

```json

  },
  "devDependencies": {
```

- 运行：`npm.cmd install` → `npm.cmd start`
  - 当前机器 PowerShell 禁用了 `.ps1` 脚本，因此文档统一使用 `npm.cmd` / `npx.cmd`。
  - 当前开发终端存在 `ELECTRON_RUN_AS_NODE=1`，直接启动 Electron 会被当成 Node 运行；本地自测脚本需先清除该变量再启动（用户双击 exe 时不受影响）。

- 自测截图：以下环境变量可让应用启动后自动截图并退出，用于验收留档

- 打包：`npm.cmd run dist`，输出 Windows 便携版 exe 到 `release/`。
- 打包后无需安装，双击运行；首次启动需等待解压，属 Electron portable 正常行为。
- v1 不做代码签名，Windows SmartScreen 可能提示“未知发布者”，属于预期。

## 9. 验收标准

### 9.1 计算正确性

- 月薪 ¥12,000、21.75 天、09:00–18:00 时，每分钟收入显示 `¥1.02`；15:45 显示已赚 `¥413.79`（允许 ±0.01 的四舍五入差异）。
- 时薪 ¥60、09:00–18:00 时，日薪 `¥540.00`，每分钟 `¥1.00`。
- 上班前已赚为 `¥0.00`；下班后已赚等于日薪。
- 跨夜 22:00–06:00 在 02:00 时正确显示工作进度 50%，而不是“已下班”。

### 9.2 状态与角色

- 09:00 前显示“还没开工”与距上班倒计时；09:00 后切换为“在岗摸鱼中”。
- 工作进度跨过 15%、40%、65%、85% 时，大肥鱼表情与气泡随之切换，且无闪烁或重复撒花。
- 到达 18:00 自动进入“下班啦”，播放一次撒花；同日再次打开不重复播放。
- 开启“降低动态效果”后无弹跳/撒花，但信息与表情仍正确。

### 9.3 交互与持久化

- 首次启动必须引导填写工资；工资为空时不能保存。
- 保存设置后主界面立即按新值计算；重启后设置仍在。
- 置顶按钮可切换窗口置顶，重启后状态保持。
- 关闭窗口后进程退出；托盘菜单可正常显示/隐藏和退出。
- 重复双击 exe 不会出现第二个窗口，而是唤醒已有窗口。

### 9.4 打包与运行

- `npm.cmd test` 全部通过。
- `npm.cmd run dist` 产出便携版 exe；在 Windows 11 上双击可离线启动。
- 应用无开发者工具、无控制台报错；窗口圆角、图标、托盘正常。
- 关闭应用后无残留进程。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Electron 包下载慢/失败 | 无法启动开发 | 使用 npm 镜像或固定版本重试；必要时先交付网页版预览，再补桌面壳 |
| 透明无边框窗口在部分 Windows 有黑边 | 视觉瑕疵 | 准备不透明圆角兜底主题；实机截图检查 |
| 动画导致 CPU 偏高 | 影响办公 | 仅使用 transform/opacity；限制粒子数量；提供降低动效开关 |
| 用户实际工资口径不同（午休、绩效、税前税后） | 金额不符合预期 | v1 标注为“参考值”，支持时薪模式；P2 增加午休扣除/自定义日薪 |
| SmartScreen 拦截 | 用户不敢运行 | README 说明未知发布者原因；提供源码与本地构建命令 |
| 大肥鱼形象版权/偏好 | 角色不满意 | 使用原创 SVG；支持后续替换本地图片，不直接使用官方素材 |
